## 3. 关键设计决策

### 3.1 判重的规范化规则（PRD 3.1.2 第 4 条，最易出错点）

PRD 允许的变换只有一种：**交换 `+` 和 `×` 节点的左右子树（交换律），不允许重结合（结合律）**。据此：

- 规范化 = 递归处理，`+`/`×` 节点先规范化左右子树，再按子树规范串排序后拼装；`-`/`÷` 不排序。
- 规范化键示例：`1+2+3`(=`(1+2)+3`) → `+ (+ (1,2),3)`；`3+(2+1)` → 同键 ⇒ **重复**（符合 PRD）。
- `3+2+1`(=`(3+2)+1`) → `+ (+ (2,3),1)` ≠ 上一键 ⇒ **不重复**（符合 PRD）。
- `23+45` 与 `45+23`、`6×8` 与 `8×6` 规范化后同键 ⇒ 重复（符合 PRD）。
- 规范化仅针对 `+`/`×`；`-`/`÷` 保持结构。

### 3.2 表达式渲染与结构保真

为避免"结构不同但渲染串相同"导致视觉重复，渲染规则固定为：

- 叶子：整数渲染为 `n`；真分数 `n/d`；带分数 `a'b/c`。
- 左子节点：当且仅当其优先级 **<** 父算子优先级时加括号。
- 右子节点：当其优先级 **≤** 父算子优先级时加括号（保证右结合结构显式化）。

效果：`(1+2)+3` → `1 + 2 + 3`（与 PRD 示例一致）；`3+(2+1)` → `3 + (2 + 1)`；`(5+3)-2` → `5 + 3 - 2` 与 `5+(3-2)` → `5 + (3 - 2)` 不冲突。

### 3.3 生成策略（保证性能与约束同时满足）

自底向上构造，而非纯随机拒绝：

1. 运算符总数随机取 `1..3`（PRD 只规定上限 3，取下限 1 以避免"单个数字"这类无意义题目——见假设）。
2. 递归构造：随机选算子，随机把剩余算子数分给左右子树，先各自构造。
3. 节点级约束修正：
   - `-`：若左值 < 右值则交换左右子树（交换不破坏子树内部约束）。
   - `÷`：交换使左值 < 右值；并要求左值 > 0 ⇒ 结果必为严格真分数（分子<分母），自动满足"不成整数、不出现假分数"。
4. 叶子生成：以一定概率取自然数 `[0, r-1]`，或取真分数 `a/b (1 ≤ a < b < r，需 r ≥ 3)`。所有**操作数**均 < r。
5. 单题构造失败（如 `÷` 无法满足）则重试；配合"已生成规范键集合"去重。
6. 设单题最大重试次数与整体失败上限；若题目空间不足（例如 `-r 1`）无法凑满 `-n`，则输出明确提示并以实际生成数量写文件（不静默失败）。

### 3.4 输出格式

- `Exercises.txt`：每行 `<表达式> = `，共 n 行，行号即题号（从 1 开始）。
- `Answers.txt`：每行一个答案（整数 / `n/d` / `a'b/c`），与题目一一对应。
- `Grade.txt`：两行，`Correct: X (i, j, ...)` 与 `Wrong: Y (i, j, ...)`，编号以 `, ` 分隔，为空时输出 `()`。
- 文件编码统一 UTF-8。

## 4. 具体改动（Proposed Changes）

### 4.1 `src/fraction.py`（新建）
- 实现不可变 `Fraction` 类：`num`/`den`，构造时约分、分母恒正。
- 支持 `+ - * /`、与 `int` 混合运算、`__eq__/__lt__` 等比较、`__hash__`。
- `from_string(s)`：解析 `n`、`n/d`、`a'b/c`（含空格容错）。
- `to_string()`：`den==1` → 整数；`0<num<den` → `n/d`；否则带分数 `a'b/c` 或整数；负数前置 `-`。
- `is_proper()`：`0 < num < den`，供除法约束校验。

### 4.2 `src/expression.py`（新建）
- 节点类型：`Num(Fraction)`、`BinOp(op, left, right)`；`OP_ADD/SUB/MUL/DIV` 常量。
- `OpNode` 记录**自身值**与**中间结果列表**，支持：
  - `evaluate()`：返回 Fraction。
  - `check_constraints(r)`：校验无负数中间结果、每个 `÷` 结果为真分数、操作数 < r、运算符数 ≤ 3。
  - `operator_count()`。
  - `canonical_key()`：按 3.1 规则生成判重键。
  - `render()`：按 3.2 规则渲染，运算符用 `+ − × ÷`（`−` 用 U+2212 或 `-`，见假设），前后空格。
- `parse(expr_str)`：递归下降解析器（词法：整数、分数/带分数、`+ − × ÷ * / ( )`），用于批改模式重算答案；与 `render()` 互逆。

### 4.3 `src/generator.py`（新建）
- `generate(n, r)`：返回 `[(expr_str, answer_str), ...]`，按 3.3 策略生成，内部持有 `seen: set[str]` 去重。
- 随机数使用 `random.Random()`；提供可选 `seed` 便于测试复现。
- 达到重试上限仍未凑满时，返回已生成结果并通过返回值标注不足（由 `main` 决定提示语）。

### 4.4 `src/grader.py`（新建）
- `grade(exercise_path, answer_path)`：
  - 逐行读取题目与答案（按行号配对）。
  - 解析题目表达式（支持结尾 `=`，忽略首尾空白），用 `expression.parse` + `evaluate` 重算标准答案。
  - 解析用户答案为 `Fraction`，与标准答案比较（`2'1/2` 与 `5/2` 视为相等）。
  - 行数不一致、表达式/答案无法解析、文件缺失 → 抛出带明确中文提示的异常。
  - 返回 `(correct_ids, wrong_ids)`，由 `main` 写出 `Grade.txt`。

## 5. 假设与决策（Assumptions & Decisions）

1. **`-r` 语义**：仅约束**题目中出现的操作数**（自然数 `0..r-1`，真分数分子分母均 `< r`）；中间结果与最终答案可 ≥ r（如 `-r 10` 仍可产生 `9 + 9 = 18`）。这是该类题目的通行做法，PRD 未明确禁止。
2. **运算符数量**：取 `1..3`（PRD 只规定上限 3）；不允许 0 个运算符，避免出现"孤零零一个数字"的无意义题目。
3. **减号符号**：输出统一使用 PRD 中的 `−`（U+2212）以贴合文档；解析器同时兼容 ASCII `-`、`*`、`/`。
4. **题目行格式**：`<表达式> = `（`=` 前后各一空格），不写入显式题号前缀，题号即行号（符合 PRD "编号从 1 开始 + 每行形如 `e = `"）。
5. **题目空间不足**：如 `-r 1` 且 `-n` 过大，无法生成足够不重复题目时，写入实际生成数量并打印警告，退出码非 0，而非死循环。
6. **批改输入**：PRD 假设输入规范，但仍做"文件存在 + 行数一致 + 可解析"三项基本校验，异常给中文提示。
7. **分数比较**：批改时按数值比较，带分数与假分数等值形（`2'1/2` vs `5/2`）判为正确。
8. **界面形态**：仅实现 CLI，不做 GUI。
